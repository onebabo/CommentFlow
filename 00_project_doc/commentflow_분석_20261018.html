1. 개요 · 설계 원칙

commentflow.py 는 즐겨찾기 작품의 회차 감상 댓글을 준비하는 CLI 도우미입니다. 댓글 문구를 만들고, 사이트 규정에 맞는지 검사하고, 클립보드 복사와 회차 페이지 열기까지만 수행합니다.

핵심 원칙 — 사이트 등록 버튼은 항상 사용자가 직접 누릅니다.
프로그램은 사이트에 자동으로 글을 쓰지 않습니다. 등록 여부는 사용자가 y 를 입력하거나 book_web 화면에서 [등록완료] 처리할 때만 DB 에 기록됩니다.
감상 메모 / 회차 내용→ 댓글 문구 생성→ 규정 검사→ DB 저장→ 복사 + 회차 페이지 열기→ 사용자가 직접 등록→ 등록완료 기록

댓글을 만드는 경로는 두 가지입니다.

① 수동 흐름 (draft → copy)

사용자가 직접 읽고 쓴 감상 메모로 후보 문구를 만들고, 골라서 저장 → 복사 → 등록. 테이블 book_comment.

② 추천 흐름 (recommend)

Gemini 가 회차 본문·이미지를 분석해 추천 댓글을 자동 생성. 테이블 book_comment_recommend. 이후 처리는 book_web /comment_list 화면에서.

3. 공통 실행 절차

  1. 표준출력 UTF-8 설정 — Windows 콘솔 한글 깨짐 방지 (sys.stdout.reconfigure).
  2. 인자 해석 — main() 이 서브커맨드를 파싱해 args.func(args) 로 해당 cmd_* 함수 실행.
  3. DB 접속 — db.get_connection() (context manager)
    config.ini 읽기 → pymysql 접속(autocommit=False, utf8mb4) → 프로세스 첫 접속이면 ensure_schema() 로 CREATE TABLE IF NOT EXISTS 실행
  4. 명령 처리 — DictCursor 로 조회·저장.
  5. 종료 처리 — 블록이 정상 종료되면 commit, 예외(SystemExit 포함)면 rollback, 마지막에 연결 종료.
오류 처리는 대부분 raise SystemExit("메시지") 로 메시지를 출력하고 종료합니다. DB 블록 안에서 발생하면 그 시점까지의 미커밋 변경은 롤백됩니다.

5. 수동 댓글 흐름: draft → copy

5-1. draft — 초안 작성

python commentflow.py draft https://toki35.com/novel/59094/6063116 --memo "주인공이 ..."
  1. 작품 ID 추출 book_id_from_url()
    URL 경로의 두 번째 조각을 작품 ID 로 사용 (/novel/59094/6063116 → 59094). 숫자가 아니면 종료.
  2. 즐겨찾기 확인 find_favorite()
    book_work_list 에 used='Y' 로 있는 작품만 허용. 없으면 종료.
  3. 후보 문구 생성 make_candidates()
    메모 끝에 문장부호(. ! ? ~)가 없으면 . 를 붙이고, 맺음말 3종을 붙여 후보 3개 생성:
    • 메모 그대로
    • 메모 + “ 다음 화도 기대하겠습니다.”
    • 메모 + “ 앞으로 어떻게 전개될지 궁금하네요.”
    각 후보마다 규정 검사 결과를 함께 표시.
  4. 사용자 선택 — 번호 선택 / e 직접 입력 / 그 외 입력은 취소(저장 없음).
  5. 최종 규정 검사 — 선택한 문구에 [불가] 가 있으면 저장하지 않고 종료.
  6. 중복 경고 — 같은 본문이 이미 등록완료(P)로 있으면 [주의] 만 출력 (저장은 진행).
  7. 저장 — book_comment 에 INSERT (status 기본값 D). 초안 번호와 다음 명령(copy <번호>) 안내.

5-2. copy — 복사 · 등록 확인

python commentflow.py copy 12
  1. 초안 조회 get_comment() — 작품 제목은 LEFT JOIN 으로 가져오며, 즐겨찾기에서 빠졌으면 “(즐겨찾기 해제됨)”. 없으면 종료.
  2. 상태 확인 — 이미 P(등록완료)면 종료.
  3. 규정 재검사 — 위반이면 종료 (규정이 바뀐 경우 대비).
  4. 클립보드 복사 + 브라우저 열기 — tkinter 로 클립보드에 본문 복사, webbrowser.open(episode_url).
  5. 상태 C 기록 — status='C'(복사함) 로 갱신 후 즉시 commit.
  6. 사용자 등록 — 사용자가 페이지에 붙여넣고 직접 등록 버튼 클릭.
  7. 등록 확인 — y 입력 시 status='P', posted_at=NOW(). Enter 만 누르면 C 상태 유지 → 나중에 copy 재실행 가능.

5-3. 상태 전이 (book_comment.status)

D 초안— copy → C 복사함— y 입력 → P 등록완료

C 상태에서 copy 를 다시 실행하면 같은 절차를 반복합니다. P 는 종착 상태입니다.

6. 규정 검사 (rules.check)

모든 경로(draft · copy · check · recommend)가 같은 함수를 사용합니다. 결과는 (errors, warnings) 이며 errors 가 하나라도 있으면 등록 불가입니다.

순서검사판정
1공백 제거 후 빈 문자열불가
2불평 키워드 포함: 유료 · 결제 · 포인트 · 크롤링 · 아류 · 인증 · 잠금 · 절차 · 왜 막 · 못 보게불가
3인사말(감사합니다 · 잘봤어요 · 수고하셨습니다 · 재밌어요 등) 제거 → 공백·기호·ㅋㅎㅠㅜ 제거 → 남은 글자 15자 미만불가
4전체 500자 초과주의

7. 추천 댓글 생성: recommend

python commentflow.py recommend --kind novel --count 20
python commentflow.py recommend --kind toon --book-id 847903 --count 5

book_web /comment_list 화면의 [댓글 생성] 버튼이 이 명령을 호출합니다. 실제 처리는 recommend.run() 에 있습니다.

7-1. 전체 흐름

  1. Gemini 설정 로드 load_gemini_config() / make_client()
    config.ini [gemini] 의 api_key(없으면 GEMINI_API_KEY 환경변수), 시작 모델 model, 전환 순서 models(없으면 내장 우선순위). 키가 없으면 종료.
  2. 작업 대상 선정 — 두 가지 모드:
    모드대상
    --book-id 없음pick_works(): 조건을 만족하는 작품을 랜덤 N개 → 작품마다 회차 1개
    --book-id 있음pick_work(): 지정 작품 1개 → 추천 없는 회차 최대 N개
  3. 회차 선정 pick_episodes()
    추천 댓글이 아직 없는 회차 중 읽은 지 오래된 회차 우선(같은 시각이면 앞 회차부터), 읽은 기록이 없으면 최신 회차 순. (2026-10-19 변경, 이전: 최근 읽은 순)
  4. 회차별 처리 recommend_for_episode() — 아래 7-3.
  5. 건별 commit · 진행 출력 — 한 건 처리할 때마다 commit 하고 [i/N] … 저장/건너뜀/오류 출력. 한 건이 예외로 실패해도 다음 건 계속.
  6. 완료 — 저장 건수와 마지막 사용 모델 출력.

7-2. 작품 선정 조건 (랜덤 모드)

구분원본 테이블조건
소설 novelbook_work_list (+ book_info 제목) used='Y' · 제목이 “[등록대기]” 로 시작하지 않음 · 본문 수집된 회차 있음 · 추천 기록 없음 · 수동 초안(book_comment) 기록도 없음
웹툰 toon / 만화 manhwa{t}_info (+ {t}_work_list URL) 이미지 수집된 회차 있음 · 수집 보류({t}_edit_holds.hold_state='H') 아님 · 추천 기록 없음

--book-id 지정 모드는 이 조건(추천·초안 기록, 보류 여부)을 따지지 않고 작품 존재만 확인합니다.

7-3. 회차 1건 처리

  1. 입력 준비
    • 소설: book_info_chapter.content 본문 (10만 자 초과 시 잘라냄). 본문 없으면 건너뜀.
    • 웹툰/만화: {t}_episode_image.file_path 로컬 이미지 중 존재하고 4.5MB 이하인 파일을 고르게 최대 8장 추출, 파일 헤더로 형식(JPEG/PNG/WEBP/GIF) 판별. 이미지 없으면 건너뜀.
  2. Gemini 분석 analyze_episode()
    시스템 프롬프트(독자 역할 + 사이트 규정 + 작성 기준 1~2문장, 공백 포함 50자 이내) + 작품·회차 정보 + 본문/이미지. JSON 스키마로 {summary, comment} 를 받음 (temperature 0.8).
  3. 규정 검사 · 재시도 — rules.check(comment) 위반이거나 50자를 넘으면 사유를 피드백으로 붙여 다시 생성. 최대 2회 시도 후에도 위반이면 저장 안 함.
  4. 원글 URL 조립 — {작품 source_url 의 도메인 또는 https://toki35.com}/{novel|webtoon|manhwa}/{work_id}/{episode_code}
  5. 저장 — book_comment_recommend 에 INSERT IGNORE (status R). 같은 (kind, work_id, episode_code) 가 이미 있으면 건너뜀.

7-4. 모델 자동 전환 (ModelSession)

gemini-3.5-flash-lite→3.5-flash→3.1-flash-lite→ 3.1-flash→2.5-flash-lite→2.5-flash→2.5-pro
  • 호출 중 429 할당량 소진 또는 404 모델 없음이면 다음 모델로 바꿔 같은 회차를 재시도.
  • 전환된 모델은 실행이 끝날 때까지 유지(이후 건도 그 모델로 시작).
  • 후보가 모두 소진되면 예외 → 해당 건 “오류” 처리 후 다음 건 진행.
  • 그 밖의 오류는 전환 없이 해당 건 오류 처리.

7-5. 이후 처리 (book_web 화면)

R 추천→S 수정저장→C 연동함 (복사 + 원글 열기)→ 사용자 직접 등록→P 등록완료

추천 댓글의 수정·연동·등록완료는 CLI 가 아니라 book_web /comment_list 에서 처리합니다.

10. 분석 메모

  • draft 저장의 commit: cmd_draft 는 명시적 commit 없이 get_connection() 블록 정상 종료 시 commit 됩니다.
  • copy 의 두 단계 commit: C 는 즉시 commit, P 는 블록 종료 시 commit. 확인 입력 중 강제 종료(Ctrl+C)해도 C 상태는 남습니다.
  • 중복 검사 범위: draft 의 중복 경고는 status='P' 인 같은 본문만 확인합니다 (초안·복사함 중복은 경고 없음).
  • draft 는 소설 전용: 작품 확인을 book_work_list 로만 하므로 웹툰·만화 URL 은 즐겨찾기 미등록으로 거절됩니다. 웹툰·만화는 recommend 경로만 지원합니다.
  • 규정 검사는 키워드 기반: 불평 키워드가 정상 감상 문맥(예: “인증 장면”)에 쓰여도 불가 처리됩니다. recommend 프롬프트는 이를 피하도록 지시합니다.
  • 클립보드는 tkinter 사용: GUI 세션이 없는 환경(원격 서비스 계정 등)에서는 copy 가 실패할 수 있습니다.
