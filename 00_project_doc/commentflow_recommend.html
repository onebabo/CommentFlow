1. 먼저 보는 결론: 이 명령의 실제 결과

8616 은 웹툰이 아니라 소설입니다.
DB 조회 결과 toon_info 와 manhwa_info 에는 8616 이 없고, book_work_list 에 소설 “검은 늑대”(used='Y')로 있습니다. 따라서 --kind toon 으로 실행하면 작품 확인 단계에서 끝나고 Gemini 호출 없이 0건입니다.
[웹툰] 작품 ID 8616 를 찾을 수 없습니다.
완료: 0건 저장

이 작품에 추천 댓글을 만들려면 구분을 소설로 지정해야 합니다.

python commentflow.py recommend --kind novel --book-id 8616 --count 3

그러면 1화 · 2화 · 3화 가 선정됩니다 (5-6 실데이터 예시). 아래 문서는 웹툰(--kind toon) 처리 절차를 기준으로 설명하고, 소설과 다른 점은 따로 표시합니다. 웹툰 실데이터 예시로는 실제 웹툰 17716 “옥탑방 야스킹” 을 사용했습니다.

3. 전체 처리 순서

  1. 진입 commentflow.main() → cmd_recommend()
    표준출력 UTF-8 설정 후 인자 해석, recommend.run(conn, "toon", 3, 8616) 호출.
  2. DB 접속 db.get_connection()
    config.ini [mysql] 로 접속 → comment_sql/*.sql 의 CREATE TABLE IF NOT EXISTS 실행 (테이블이 있으면 변화 없음).
  3. 구분 확인 — kind 가 novel / toon / manhwa 가 아니면 종료.
  4. Gemini 준비 load_gemini_config() → make_client() → ModelSession
    config.ini [gemini] 의 api_key (없으면 GEMINI_API_KEY 환경변수), 시작 모델, 전환 우선순위를 읽어 클라이언트 생성. API 키가 없으면 작품 확인 전에 여기서 종료합니다.
  5. 작품 확인 pick_work() — 4장. 없으면 “찾을 수 없습니다 / 완료: 0건 저장” 출력 후 종료. 8616 은 여기서 종료.
  6. 회차 선정 pick_episodes(cursor, "toon", 8616, 3) — 5장. 최대 3개를 한 번에 정함.
  7. 시작 안내 출력 — 대상 회차 수, 시작 모델, 모델 전환 우선순위.
  8. 회차별 처리 반복 recommend_for_episode() — 6장. 건마다 바로 commit 하고 [i/3] 결과 출력. 한 건에서 예외가 나도 “오류: …” 출력 후 다음 건 계속.
  9. 완료 — 완료: N건 저장 (마지막 모델 …) 출력, 접속 종료 시 남은 변경 commit.

4. 작품 확인 (pick_work)

SELECT t.toon_id AS work_id, t.title, COALESCE(w.source_url, t.source_url) AS source_url
  FROM toon_info AS t
  LEFT JOIN toon_work_list AS w ON w.toon_id = t.toon_id
 WHERE t.toon_id = 8616
  • 기준 테이블은 toon_info. 여기에 행이 없으면 작품 없음으로 처리합니다.
  • 원글 주소(source_url)는 toon_work_list 값을 우선, 없으면 toon_info 값.
  • 작품 지정 모드에서는 다음을 확인하지 않습니다: toon_work_list.used(사용 여부), toon_edit_holds(수집 보류), 이미 추천 댓글이 있는지. (이 조건들은 --book-id 없이 실행하는 랜덤 모드에서만 적용됩니다.)

5. 회차 3개 선정 규칙 (pick_episodes) — 상세

한 번의 SQL 로 후보를 거르고 → 우선순위로 정렬하고 → 위에서 3개를 자릅니다.

SELECT e.episode_code, e.episode_no, e.episode_title
  FROM toon_episode AS e
  LEFT JOIN toon_episode_read AS r
         ON r.toon_id = e.toon_id AND r.episode_no = e.episode_no
 WHERE e.toon_id = 8616                       -- ① 이 작품의 회차
   AND e.has_images = 1                       -- ② 이미지 수집 완료
   AND NOT EXISTS (SELECT 1 FROM book_comment_recommend AS cr
                    WHERE cr.kind = 'toon' AND cr.work_id = e.toon_id
                      AND cr.episode_code = e.episode_code)   -- ③ 추천 댓글 없음
 ORDER BY (r.toon_id IS NOT NULL) DESC,       -- ㉠ 읽은 회차 먼저
          r.read_at,                          -- ㉡ 읽은 지 오래된 순
          CASE WHEN r.toon_id IS NOT NULL
               THEN e.episode_no END,         -- ㉢ (읽은 회차) 같은 시각이면 앞 회차부터
          e.episode_no DESC                   -- ㉣ (안 읽은 회차) 최신 회차부터
 LIMIT 3                                      -- --count
2026-10-19 변경: 읽은 회차는 최근에 읽은 순 → 읽은 지 오래된 순으로 바뀌었습니다 (recommend.py pick_episodes, 소설·웹툰·만화 공통).
작품의 전체 회차 toon_episode WHERE toon_id = 8616
② 이미지 수집 완료 회차만 has_images = 1
③ 추천 댓글이 아직 없는 회차만 book_comment_recommend 에 같은 회차 없음
㉠~㉣ 우선순위 정렬 읽은 회차(오래 전에 읽은 순) → 안 읽은 회차(최신 순)
위에서 3개 (LIMIT 3)

5-1. 후보 조건 (WHERE)

조건내용세부
① 작품e.toon_id = 8616본편/외전 구분(episode_type MAIN/SIDE)은 따지지 않으므로 외전도 후보가 됩니다.
② 이미지 수집 완료e.has_images = 1has_images 는 계산 컬럼: image_cnt > 0 AND saved_image_cnt >= image_cnt 이면 1. 즉 뷰어 기준 이미지 수만큼 로컬 저장이 끝난 회차만 후보. 일부만 받은 회차는 제외됩니다.
단, 실제 파일이 지금 디스크에 있는지는 여기서 확인하지 않습니다 (6장에서 확인).
③ 추천 없음NOT EXISTS book_comment_recommend(kind='toon', work_id, episode_code) 가 같은 행이 있으면 제외. 상태(R/S/C/P)와 무관 — 이미 등록완료(P)된 회차도, 수정 중(S)인 회차도 모두 제외. 추천 행을 삭제하면 다시 후보가 됩니다.

5-2. 우선순위 (ORDER BY)

순서정렬 키의미
㉠(r.toon_id IS NOT NULL) DESC toon_episode_read 에 읽은 기록이 있는 회차(1)를 기록이 없는 회차(0)보다 먼저.
읽음 기록은 episode_no 로 연결합니다 (episode_code 아님). toon_episode_read 의 PK 가 (toon_id, episode_no) 라서 회차가 중복으로 나오지는 않습니다.
㉡r.read_at (오름차순) 읽은 회차끼리는 읽은 지 가장 오래된 회차 먼저.
읽지 않은 회차는 read_at 이 NULL 이라 모두 같은 값으로 취급 → 다음 키로 넘어감.
㉢CASE WHEN 읽음 THEN e.episode_no END (오름차순) 읽은 회차 중 같은 초에 여러 회차를 읽은 경우(read_at 동일) 앞 회차(번호 작은 순)부터.
읽지 않은 회차는 NULL 이라 영향 없음.
㉣e.episode_no DESC 읽지 않은 회차끼리는 회차 번호가 큰(최신) 회차 먼저 (변경 없음).

5-3. 경우별로 정리한 선정 결과

상황선정되는 3개
읽은 회차가 3개 이상 (추천 없는 것 기준)읽은 지 가장 오래된 3개 회차 (같은 시각에 읽었으면 앞 회차부터)
읽은 회차가 1~2개읽은 회차 전부(오래된 순) + 나머지는 읽지 않은 회차 중 번호가 큰 순
읽은 기록이 전혀 없음이미지 수집 완료된 회차 중 번호가 가장 큰 3개 (최신 3화)
후보가 3개 미만있는 만큼만 (0개면 “추천 없는 회차 0개” 출력 후 바로 완료)
같은 명령을 다시 실행방금 저장된 회차는 ③ 으로 빠지므로 그다음 3개가 선정됨

5-4. 선정 후 탈락 — 빈자리를 채우지 않음

3개는 처리 시작 전에 한 번에 확정됩니다. 처리 중 한 회차가 건너뛰어지거나 오류가 나도 다음 순위 회차로 대신 채우지 않습니다. 그래서 --count 3 이라도 저장은 0~3건입니다.

선정 3개→ 이미지 파일 없음 → 건너뜀 규정 2회 실패 → 저장 안 함 API 오류 → 오류 이미 있음(동시 실행) → 건너뜀

6. 회차 1건 처리 (recommend_for_episode)

  1. 이미지 목록 조회 episode_images() 
    SELECT file_path FROM toon_episode_image
 WHERE episode_code = %s AND file_path IS NOT NULL ORDER BY page_no
  2. 파일 거르기 — 경로의 파일이 실제로 존재하고, 크기가 0 초과 4.5MB 이하인 것만 남김 (API 이미지 1장 한도 5MB 대비).
  3. 고르게 8장 뽑기 — 남은 파일이 8장보다 많으면 step = 개수 / 8, int(i × step) (i = 0~7) 번째 파일을 선택.
    예: 49장 → step 6.125 → 인덱스 0, 6, 12, 18, 24, 30, 36, 42 → 1·7·13·19·25·31·37·43 번째 파일. (인덱스는 거른 뒤 목록 기준이라, 중간 파일이 빠졌으면 page_no 와 어긋날 수 있음)
  4. 형식 판별 — 파일 앞부분 바이트로 JPEG / PNG / WEBP / GIF 판별, 그 외 형식은 제외. 남은 이미지가 0장이면 “읽을 수 있는 회차 이미지 없음 → 건너뜀”.
  5. Gemini 분석 analyze_episode()
    • 시스템 프롬프트: “{웹툰}을 꾸준히 보는 독자” 역할 + 이미지에 보이는 내용만 근거로 + 사이트 규정 + 1~2문장·공백 포함 50자 이내 (MAX_COMMENT_CHARS)
    • 입력: 이미지 N장 + “작품: … / 회차: … / 위 이미지 N장은 이 회차에서 순서대로 고르게 뽑은 장면입니다.”
    • 출력: JSON {summary, comment} (temperature 0.8)
    • 429(할당량) · 404(모델 없음)이면 다음 모델로 바꿔 같은 회차 재요청. 바뀐 모델은 남은 회차에도 유지.
  6. 규정 검사 · 재시도 — rules.check(comment) 위반이거나 50자를 넘으면 사유를 붙여(“이전에 쓴 댓글이 규정 검사에서 거절됐습니다: …”) 다시 요청. 최대 2회 시도해도 위반이면 “규정 통과 실패 → 저장 안 함”.
  7. 원글 URL 조립 — {source_url 의 scheme://host}/webtoon/{toon_id}/{episode_code}. source_url 이 없으면 https://toki35.com.
    예: https://toki35.com/webtoon/17716/u-mq12tjtz-8w55
  8. 저장 — INSERT IGNORE INTO book_comment_recommend (kind='toon', work_id, episode_code, episode_no, 제목들, source_url, summary, body, model), status 기본 R. 고유키 (kind, work_id, episode_code) 충돌이면 “추천이 이미 있음 → 건너뜀”.
  9. commit — run() 이 건마다 commit → book_web 화면에서 진행 상황이 바로 보임.

8. 주의 · 확인 사항

  • kind 와 ID 가 맞아야 합니다. 같은 숫자 ID 가 소설·웹툰·만화에 따로 존재할 수 있고, 작품을 찾지 못해도 오류가 아니라 “0건 저장”으로 끝납니다. book_web 에서 [댓글 생성]을 호출할 때 넘기는 구분 값도 함께 확인해 보세요.
  • 이미지 파일은 실행하는 PC 의 경로(D:\booktoon\{toon_id}\{episode_no}\…)를 직접 읽습니다. 2026-10-18 조회 시 17716 의 70~72화는 이 PC 에서 사용 가능한 파일이 0장이었습니다 (DB 경로 72 · 49 · 51건, 실제 파일 없음). 변경 후 선정되는 1~3화도 파일이 있는지 실행 전에 확인하세요.
  • 건너뛴 회차는 계속 1순위로 남습니다. 저장되지 않았으므로 ③ 에 걸리지 않아, 다음 실행에서도 같은 회차가 다시 선정됩니다. 이미지 파일을 다시 수집하기 전까지 같은 결과가 반복됩니다.
  • 읽지 않은 최신 회차는 뒤로 밀립니다. 읽은 기록이 하나라도 있는 작품은, 추천 없는 읽은 회차가 모두 소진될 때까지 안 읽은 최신 회차가 선정되지 않습니다.
  • 랜덤 모드(--book-id 없음)에도 같은 순서가 적용됩니다. 작품마다 1회차를 고를 때도 이제 읽은 지 가장 오래된 회차가 선택됩니다.
  • API 키 확인이 작품 확인보다 먼저입니다. 작품이 없더라도 Gemini 키가 없으면 키 안내 메시지로 종료합니다.
  • 사이트 등록은 하지 않습니다. 저장된 추천(R)은 book_web /comment_list 에서 수정(S) → 연동(C) → 사용자 직접 등록 → 등록완료(P) 로 처리합니다.
